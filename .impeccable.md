# Impeccable

Design context for `beans-frontend`. Loaded by design skills before any design work.

## Design Context

### Users

Developers running a local web UI over the [`beans`](https://github.com/hmans/beans) CLI — a
local-first, Markdown-backed issue tracker. The project began as a single-user personal tool and is
now public on GitHub, so **audit and design for public OSS users**: unknown developers on varied
hardware, operating systems, browsers, and assistive technology.

Context of use: a second monitor or a background tab, open alongside an editor and a terminal.
Sessions are short and frequent — check what's ready to work on, open a bean, edit a field, get back
to code. Often driven in parallel with coding agents that mutate the same `.beans` files on disk,
so the UI must reflect external changes without the user re-reading the whole screen.

Jobs to be done:

- See what's actionable across every discovered project, not just one.
- Find a specific bean fast (global search, `⌘K`).
- Edit metadata and relationships inline without a context switch.
- Read a bean's body as prose — this is a reading surface, not just a form.

### Brand Personality

**Considered, quiet, durable.** The voice of a well-kept engineering logbook: plain language, no
marketing register, no exclamation. The interface should evoke _calm competence_ — the user should
feel the tool is dense with information yet never shouting.

Emotional goals: confidence over delight, clarity over novelty. Nothing should feel provisional.

### Aesthetic Direction

**Settled — a warm "engineering logbook."** The direction is decided and is not up for
relitigation; design work happens _within_ it. Deviations from it are defects.

- **Palette:** warm paper ground (`--paper`), ink text (`--ink`), hairline rules (`--hairline`).
  Restrained accents. Dark mode is a warm charcoal counterpart, never near-black-blue.
- **Type:** serif for display and headings, sans for body and UI chrome, mono for bean IDs and code.
- **Structure:** hairline separators carry hierarchy. Not cards, not shadows, not elevation.
- **Signals:** type tags are small, muted, type-colored. Status is a dot plus text, never a loud pill.
- **Charts:** editorial palette, legible in both themes.
- **Theme:** light and dark are equal citizens via `light-dark()`; neither is the "real" one.

Anti-references — explicitly not this: indigo/purple gradients, glassmorphism, glowing accents on
dark, emoji heroes, cookie-cutter card grids, gradient text, hero-metric layouts.

### Design Principles

1. **The token system is the system.** Every color, and every spacing value that carries meaning,
   resolves through `tokens.css`. A hard-coded hex in a component is a bug, not a shortcut.
2. **Hairlines, not boxes.** Convey structure with rules, spacing, and type weight. Reach for a
   container only when grouping genuinely requires one, and never nest them.
3. **WCAG AA is the floor, and it is verified.** Contrast pairs are chosen against a computed ratio
   and the reasoning is left in a comment. Keyboard paths and focus order are part of the feature,
   not a follow-up.
4. **Adapt for mobile, never amputate.** Narrow viewports get a different density and a shallower
   hierarchy treatment — the same data and the same capabilities.
5. **Every word earns its place.** No copy that restates its own heading. Empty states teach the
   interface rather than announcing emptiness.
